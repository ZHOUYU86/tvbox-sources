# 两个BT影视（bttwo.life）攻坚笔记 —— wasm 播放签名破解 + jar 爬虫

日期：2026-10-13
状态：✅ 全链路验收通过（分类翻页/搜索/多线路/画质档位/播放可用），jar 上线 v2

## 一、站点概况

- 站点：https://www.bttwo.life（镜像 https://www.bttwo.vip）
- 特点：影视资源站，SSR 网页直出（无 JSON 列表 API）
- 分类：`/movie`（电影）`/tv`（剧集）`/anime`（动漫）—— 单页约 50+ 条，**无分页机制**
- 搜索：`GET /search?q={关键词}`（GET 表单）
- 详情：`/play/{短id}`（如 ch4n35g5j）
- 播放：`GET /video/play?p={dataid}&v={短id}&q={画质}&s={签名}&t={毫秒}&k={key}`

## 二、播放签名破解（核心攻坚，最终铁证）

### 页面关键凭证
- `<meta id="nb-st" content="{服务端毫秒时间戳}">` —— 时效校验，t 过期会 401
- `<meta id="nb-plt" content="">` + JS 回填 Date.now()
- `window.myuserlink` —— playkey，未登录默认 `X1VUXk9bXQYHAw4FCgc7IUleVk9e`
- `window._pdf` —— base64 解码 = 播放 CDN 列表（oss.douyinbit.com 等）

### 破解路径（三步走）
1. **wasm 黑盒**：页面加载 `nbmovie_wasm.js` + `nbmovie_wasm_bg.wasm`（57856B）
   - 用 wasmtime 模拟 14 个 host 函数（getElementById 返回 nb-st/nb-plt 引用、content 回填、now 返回 Date.now()）
   - 导出 `build_play_url(dataid, secret, quality, playkey)` → 生成的 URL 与浏览器逐字符一致
2. **反编译 + 插桩**：
   - wasm2wat 反编译 571893B 的 wasm.wat；导出函数 = func14
   - 在 func14 返回前插入 memory.copy dump 内存 → 读栈帧：
     - s 在栈帧 192/240
     - 外层哈希态 f9b349c5... 在 208/256
     - 消息 String（dataid:t:secret，29 字节）在栈帧 108（112/116 = {地址, 29}）
   - 关键发现：消息 = `"dataid:t:secret"`（冒号分隔），**不是 playkey**
3. **公式验证**：
   - 先试 HMAC 变体（opad=0x6A）→ 不匹配（645cf9d4...）
   - 试**标准 HMAC-SHA256** → **一击命中**！

### 最终公式（写 jar 直接用）
```
s = hex(HMAC-SHA256(key=secret, msg="{dataid}:{t}:{secret}"))[0:16]  # 前16字节hex
    其中 secret = v = 播放短id（如 ch4n389bb）
    t = 当前毫秒时间戳（与 nb-st 接近即可）
k = base64(playkey XOR 'nbmovie2024secretkey')   # 18字节盐循环XOR
    playkey 未登录 = X1VUXk9bXQYHAw4FCgc7IUleVk9e（28字节）
```

### 双重铁证
- 样本复现：dataid=40037、v=ch4n389bb、t=1791888341754
  → s=`5eecd402e3729c0531268e04f351ecc1`、k=`NlM7Oi4CXFBoY207JBRGIzcMBk4nNwEKIAJcVw==`
  → HMAC 完整 32 字节 = `5eecd402...f9b349c523d6f5b8e165f5fbd09cf2d0`
  → **后 16 字节 f9b349c5... 与插桩栈帧 dump 逐字节一致**
- 真实请求：s/k 公式生成 URL → **HTTP 200**，返回 m3u8 直链
  `https://zijieapi.douyinbyte.com/m3u8/{32hex}.m3u8`

### 踩过的坑（勿重试）
- simple md5/sha1/sha256 各种拼接 → 0 命中
- HMAC 变体（opad=0x6A）+ 数百拼接 → 0 命中
- wabt wasm-decompile/wasm2c 崩溃（wasm2wat.exe 可用）
- 依赖实验"playkey 变 s 变"是**没控制 t**（每次 wasm 运行 Date.now() 都不同）造成的假象
  —— 真相：s 只依赖 (secret, dataid, t)；k 只依赖 playkey

## 三、jar 爬虫结构（Bttwo.java）

- 模板：WwwKeke.java（可可影视，同工程）
- 分类：`/movie` `/tv` `/anime` → SSR 卡片解析
  - 条目 `<a href="/play/{id}" class="block">`，标题 `<h3 class="text-white...">`（搜索页在 img alt），图 `data-src="..."`（&amp; 要还原）
- 详情 `/play/{id}`：
  - 标题 og:title（去掉 " - 第N集" 后缀）
  - 图 og:image；简介 meta description
  - 年份/导演：meta keywords 逗号分隔（顺序：片名,年份,类型,地区,语言,导演 → 导演在最后）
  - 线路：`x-data="episodeManager(1, 1, [{ lineName: 'alists', episodeCount: 21 }])"` → lineName 列表
  - 选集：`<a href="/play/{集vid}" ... data-line="{线路}" data-episode="{N}" dataid="{播放id}">` → 按 data-line 分组
  - **集名统一"第N集"**（a 标签内容含 Alpine 属性不可靠）
- 播放（playerContent）：
  - 集数 URL = `{SITE}/play/{vid}?p={dataid}`（dataid 塞查询参数）
  - 生成 s/k → 请求 /video/play → 解析 quality_urls[0].url → m3u8
  - 返回 header（UA + Referer）

## 四、分类翻页攻坚（/filter 全站筛选，最终方案）

- 初版：`/movie` `/tv` `/anime` 单页精选（约 50-60 条），`?page=2`、`/movie/2`、`/page/2`、`/api/movie?page=2` 全部同页或 404 —— **单页无分页，已证死路**
- **突破口**：右上角三横线菜单 → `/filter` 筛选页（用户指路）
  - `/filter?classify=1` 电影、`2` 电视剧、`3` 动漫、`4` 综艺（tab 点击实测 URL 变化确认）
  - 附带完整筛选：`?areas=N`（地区）、`?types=N`（类型）、`?years=N`（年份）、`?tags=N`（标签）、`?sort_by=update_time|hits|score&order=desc`（排序）
  - **`?page=N` 真实分页**：全库 5381 条 / 225 页，每页约 24-26 条（页间内容不同已验证）
- **jar 方案**（Bttwo.java）：
  - movie → `/filter?classify=1`、tv → `/filter?classify=2`、anime → `/filter?classify=3`、filter(全部影片) → `/filter`
  - page>1 时拼 `&page=N`；page() 的 total 用大数 9999 占位，OK影视 翻到空页自然停
- **卡片解析与 /movie 一致**（`<a href="/play/{id}" class="block">` + h3 标题 + data-src 图）—— parseList 直接复用
- 验收：✅ 用户确认「全部影片/剧集/电影/动漫」均可翻页

## 五、OK影视 jar 缓存大坑（v2 换名解决）

- **现象**：改 jar 重传 GitHub 后，用户重新导入配置仍跑旧逻辑（不能翻页），logcat 无 TV-BTTWO 日志
- **根因**：OK影视 的 jar 缓存按 **jar URL 的 hash** 记，URL 没变 → 一直用缓存旧 jar（md5 变化不触发重新下载）
- **解决（三管齐下）**：
  1. 清 OK影视 缓存：`rm -f /data/user/0/com.fongmi.android.tv/cache/jar/*.jar`
  2. **jar 换新文件名上传**（custom_spider_bttwo.jar → custom_spider_bttwo_v2.jar）→ URL 变 → 必然下载新版
  3. 配置 spider URL 同步指向新文件名 + 新 md5
- 铁律：**以后任何 jar 更新都换新文件名**，不要覆盖同名

## 六、画质档位（多线路）

- 站点播放 q 参数：4K→`1`、1080→`1080`、720→`720`、480→`480`
- jar 详情线路生成 4 条：4K / 1080P / 720P / 480P（线路名 + 各自 q 值）
- 说明：4K 线路可能限会员（未登录可能失败），可考虑调序 1080 优先

## 七、其他经验
- 站点整体加载偏慢（首页/分类 SSR 响应时间较长）—— 播放走 CDN（zijieapi.douyinbyte.com）较快
- 编译：改 Java 文件禁止 PowerShell Set-Content（加 BOM 导致 javac 报 `非法字符: '\ufeff'`），须 `[IO.File]::WriteAllText(..., (New-Object Text.UTF8Encoding $false))`
- GitHub 上传：Contents API GET 大响应易 IncompleteRead（重试 4 次内成功），GET 拿 sha → PUT 覆盖；新文件 PUT 无 sha
