# 星空4K APP逆向与TVBox接口开发笔记

## 一、项目概述

**目标**：将星空4K APP（Ver.1.2.8）逆向开发为TVBox type=1接口，实现首页/分类/详情/搜索/播放全功能。

**最终状态**：接口开发完成，首页/分类/详情/搜索全部正常，播放功能通过302重定向方案验证可用，但因星空4K官方vodParse接口有解析次数限制（需观看激励视频广告），且APP在模拟器中频繁闪退，最终决定放弃该接口。

## 三、逆向过程

### 3.1 JADX反编译

使用JADX对APK进行反编译，发现：
- 代码被NM Protect加固，大部分Java代码被混淆
- 网络请求相关逻辑在native层（libnmmp.so）中实现
- API基础路径格式：`DOMAIN/api/vod/` + 接口名

### 3.2 动态配置与域名发现

APP启动时会请求动态配置URL获取最新API域名：
- 动态配置URL：`https://xk628.xkgzs.xyz/1.txt`
- 最新API域名：`https://xk21127.xkgzs.xyz`
- API基础路径：`https://xk21127.xkgzs.xyz/api/vod/`

### 3.3 AES加密密钥提取

所有API返回数据均为AES/CBC/PKCS5Padding加密的Base64字符串。

在libnmmp.so中搜索到密钥：
```
密钥 = IV = 11620jkjkSdkeYun （16字节）
```

解密方法：
1. Base64解码返回的data字段
2. 使用AES-128-CBC解密，key和IV均为`11620jkjkSdkeYun`
3. 去除PKCS7填充
4. 得到JSON格式的明文数据

### 3.4 请求头要求

所有API请求必须携带以下请求头：
```
User-Agent: okhttp/3.14.9
Content-Type: application/x-www-form-urlencoded
app-device-id: 2db44746d35bf3276af525f1209e44ca7
app-os-type: android
app-version-code: 128
```

请求方式：POST，参数为form-urlencoded格式。

## 四、API接口分析

### 4.1 接口列表

| 接口名 | 功能 | 关键参数 |
|--------|------|----------|
| init | 初始化 | 无 |
| verify | 验证 | 无 |
| launchReport | 启动报告 | 无 |
| typeFilterVodList | 分类影片列表 | type_id, page, page_size |
| vodDetail | 影片详情 | vod_id |
| searchSuggestions | 搜索建议 | keyword |
| vodParse | 播放地址解析 | vod_id, player_source_id, player_code, episode_index等 |

### 4.2 首页/分类数据

- 首页数据：调用typeFilterVodList获取推荐列表
- 分类数据：调用typeFilterVodList，参数type_id为分类ID
- 返回字段：`recommend_list`（影片列表）、`total`（总数）

### 4.3 详情页数据结构

调用vodDetail接口，返回数据结构：
- `vod`：影片基本信息（名称、海报、简介、导演、演员等）
- `player_source_list`：播放源元数据列表，每个源包含：
  - `id`：播放源ID
  - `player_code`：播放源代码（如zijianm3u8、youku、Ace等）
  - `player_name`：播放源名称（如新阿里4k、y纯享、动漫4k等）
  - `jx_type`：解析类型
  - `player_parse_type`：播放解析类型
  - `player_kernel_type`：播放内核类型
- `vod_play_url_list`：各播放源的集数列表，每个源包含：
  - `player_code`：播放源代码（与player_source_list匹配）
  - `urls`：集数列表，每集包含`name`（集数名）和`episode_index`（集数索引）

**关键**：详情页返回的每集url字段全为空，真实播放地址需要调用vodParse接口获取。

### 4.4 搜索接口

调用searchSuggestions接口，参数`keyword`为搜索关键词。

## 五、vodParse播放地址解析（核心突破）

### 5.1 问题

详情页返回的每集url字段全为空，真实播放地址需要调用vodParse接口获取。但vodParse的参数格式在native层（libnmmp.so）的`parseByServerHttp`方法中动态构造，无法直接从Java代码中看出。

### 5.2 暴力测试过程

经过数百种参数组合测试，包括：
- camelCase格式（vodId、playerSourceId等）
- 下划线格式（vod_id、player_source_id等）
- JSON body格式
- form-data格式
- GET方式
- POST方式

最终发现**下划线格式参数成功**：

```
vod_id={影片ID}&player_source_id={播放源ID}&player_code={播放源代码}&episode_index={集数索引}&jx_type=1&player_parse_type=1&player_kernel_type=0
```

### 5.3 返回数据

vodParse返回解密后的数据：
```json
{
  "play_url": "真实播放地址（m3u8）",
  "official_url": "官方播放地址（如腾讯视频）",
  "danmu_url": "弹幕地址",
  "is_trial": true,
  "trial_duration_seconds": 900,
  "trial": {
    "enabled": true,
    "available": true,
    "current_episode_allowed": true,
    "episode_count": 3,
    "duration_seconds": 900,
    "trial_episode_index": 0
  }
}
```

**重要发现**：所有vodParse返回的播放地址均为**试看地址**（is_trial=true），试看时长900秒（15分钟），完整播放需要星空4K APP登录会员。

### 5.4 解析次数限制

vodParse接口有**解析次数限制**，当次数用完时返回：
```json
{
  "code": 10001,
  "msg": "本次解析次数已用完，观看激励视频后可继续播放"
}
```

限制方式：按IP地址限制（换设备ID无效），需要在星空4K APP中观看激励视频广告才能恢复解析次数。

## 六、TVBox type=1接口开发

### 6.1 接口规范

TVBox type=1接口（苹果CMS格式）：
- 首页：`GET /api.php/provide/vod` → 返回分类列表+推荐影片
- 分类页：`GET /api.php/provide/vod?ac=detail&t={分类ID}&pg={页码}` → 返回分类影片列表
- 详情页：`GET /api.php/provide/vod?ac=detail&ids={影片ID}` → 返回影片详情+播放源+集数
- 搜索：`GET /api.php/provide/vod?wd={关键词}` → 返回搜索结果
- 播放：`GET /api.php/provide/vod?ac=play&url={播放地址}` → 返回真实播放地址

### 6.2 播放源与集数格式

TVBox详情页返回的播放源和集数格式：
- `vod_play_from`：播放源名称，多个源用`$$$`分隔
- `vod_play_url`：集数数据，格式为`源1$$$源2$$$...`，每个源的集数用`#`分隔，每集格式为`集数名$播放地址`

### 6.3 服务实现

使用Python的http.server模块实现接口服务：
- 脚本路径：`D:\tvbox\spider_dev\dashixiong\xingkong_api_server.py`
- 端口：8897
- 接口地址：`http://192.168.0.26:8897/api.php/provide/vod`

## 七、播放功能排查过程（核心难点）

### 7.1 方案一：编码url + ac=play（失败）

**思路**：详情页每集url编码播放源信息（格式`vod_id|player_source_id|player_code|episode_index|jx_type|player_parse_type|player_kernel_type`），TVBox点击播放时ac=play请求携带此编码url，服务端解析后调用vodParse获取真实地址。

**失败原因**：TVBox根本不发ac=play请求。原因是详情页编码url含`|`符号，TVBox解析vod_play_url失败。

### 7.2 方案二：直接返回原始m3u8地址（失败）

**思路**：ac=play直接返回vodParse获取的原始m3u8地址。

**失败原因**：原始m3u8为AES-128加密，TVBox播放器不支持，播放打圈圈。

### 7.3 方案三：服务端代理m3u8（失败）

**思路**：服务端下载m3u8，替换密钥和ts地址为/proxy代理地址，TVBox请求/proxy时服务端实时解密ts文件。

**失败原因**：TVBox请求了代理的m3u8，但**不请求/proxy的ts文件**，无法播放。

### 7.4 方案四：内嵌m3u8内容到ac=play返回（失败）

**思路**：ac=play的url字段直接返回`#EXTM3U`开头的完整m3u8内容（已去掉加密标记，ts地址为代理地址），让播放器直接解析。

**失败原因**：TVBox播放器仍不请求代理的ts文件。

### 7.5 方案五：服务端完全解密（不稳定）

**思路**：服务端下载m3u8和所有ts文件，AES解密后保存到本地，返回本地m3u8的HTTP地址。

**问题**：需要下载所有ts文件（可能几百MB），第一次播放很慢；且服务端处理大文件时容易崩溃，服务不稳定。

### 7.6 方案六：详情页http代理地址 + 302重定向（成功！）

**思路**：详情页每集url直接设置为**http开头的本地代理地址**：
```
http://192.168.0.26:8897/play_redirect?data=<base64编码的播放源信息>
```

TVBox点击集数后，直接请求该http地址，服务端`/play_redirect`路由：
1. 解析data参数（base64解码得到播放源信息）
2. 调用vodParse获取真实m3u8地址
3. 返回302重定向到真实地址

**成功原因**：
- 详情页url以http开头，TVBox能正确解析
- TVBox点击后直接请求该地址，不需要发ac=play
- 302重定向后，TVBox播放器直接播放原始m3u8地址
- 对于AES-128加密的m3u8，TVBox播放器（ExoPlayer/IJKPlayer）实际支持解密播放

**用户确认**：此方案播放成功，用户反馈"可以了"。

## 九、mitmproxy抓包过程

### 9.1 目的

为了验证API请求格式和参数，使用mitmproxy对APP进行HTTPS抓包。

### 9.2 步骤

1. **构建内置mitmproxy CA证书的APK**：
   - 使用apktool 2.9.3反编译APK
   - 添加`network_security_config.xml`，配置信任用户证书
   - 将mitmproxy CA证书放入`res/raw/mitmproxy_ca.crt`
   - 重新打包签名

2. **patch libpine.so**：
   - Pine框架会干扰抓包，需要patch libpine.so
   - 将JNI_OnLoad方法直接返回，跳过Pine框架初始化
   - patch脚本：`patch_pine.py`

3. **安装并抓包**：
   - 将patch后的APK安装到雷电模拟器14
   - 启动mitmdump，设置模拟器代理
   - 成功解密HTTPS流量，验证init/verify/launchReport请求

### 9.3 遇到的问题

- APP存在稳定性问题，第二次启动崩溃（Resources$NotFoundException）
- 解决方案：清除数据后第一次启动，抓包完成后不再重启

## 十、APP在模拟器中闪退问题

### 10.1 现象

星空4K APP在雷电模拟器14中频繁闪退，有时能打开，有时打开后立即崩溃。

### 10.2 可能原因

- Pine框架加固与模拟器兼容性问题
- NM Protect加固检测到模拟器环境
- APP对设备环境有校验

### 10.3 临时解决方案

- 清除APP数据后第一次启动，通常能成功打开
- 不要频繁重启APP
- 避免在APP内进行过多操作

## 十一、最终结论

### 11.1 已完成

- ✅ APK逆向完成，API接口全部分析清楚
- ✅ AES加密密钥提取成功，所有接口能正常调用
- ✅ vodParse播放地址解析参数格式突破（下划线格式）
- ✅ TVBox type=1接口开发完成（首页/分类/详情/搜索）
- ✅ 播放功能通过302重定向方案验证可用
- ✅ 全播放源检测完成，明确各源可用性

### 11.2 未解决/放弃原因

1. **vodParse解析次数限制**：星空4K官方限制了每IP的解析次数，用完后需要观看激励视频广告才能恢复。接口无法绕过此限制。

2. **APP在模拟器中频繁闪退**：无法稳定使用APP观看激励视频来恢复解析次数。

3. **部分播放源不可用**：动漫4k、奇迹、美国2k、京东4k等源因防盗链/地址过期/无数据等原因无法播放，这是源本身的问题，非接口代码问题。

4. **所有播放地址均为试看地址**：vodParse返回的地址is_trial=true，只能看15分钟，完整播放需要登录会员。

### 11.3 经验总结

1. TVBox type=1接口中，详情页的每集url如果包含特殊字符（如`|`），会导致TVBox解析失败，不发ac=play请求。解决方案是将url设置为http开头的代理地址。

2. TVBox播放器（ExoPlayer/IJKPlayer）实际支持AES-128加密的m3u8播放，不需要服务端解密。

3. 302重定向是解决播放地址动态获取的有效方案，服务端获取真实地址后302重定向，播放器自动跟随。

4. 逆向加固APP时，mitmproxy抓包需要patch加固框架（如Pine），否则无法解密HTTPS流量。
