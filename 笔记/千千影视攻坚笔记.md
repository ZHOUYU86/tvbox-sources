## 三、【重大坑】播放页 player_data 分号问题

### 症状
- OK影视 里详情、线路、选集全部正常，但播放报"播放地址解析失败"
- 幺爸反馈：线路全部检测不出来，要跳到采集接口才播

### 根因（实测实证）
播放页内嵌 `var player_data={...}`，但：
- 《我不是大师》的 player_data **以分号结尾**：`...;"}`
- 《魅影神捕》(68337) 的 player_data **没有分号**，直接 `}` + `</script>`

旧正则 `player_data\s*=\s*(\{[^;]*?\});` **死等结尾分号**，导致无分号剧集全部匹配失败 → 播放解析失败。用 `probe_qqys_raw.py` 实锤：花括号 1:1 平衡、无分号。

### 修复方案（已上线）
用**花括号平衡提取**，不依赖分号：

```java
int idx = html.indexOf("player_data=");
while (idx >= 0) {
    int b = html.indexOf('{', idx);
    if (b >= 0) {
        int depth = 0; int i = b;
        while (i < html.length()) {
            char c = html.charAt(i);
            if (c == '{') depth++;
            else if (c == '}') { depth--; if (depth == 0) { /* 提取 substring(b, i+1) */ break; } }
            i++;
        }
    }
    idx = html.indexOf("player_data=", idx + 1);
}
```

只接受 `real.contains(".m3u8") || real.contains(".mp4")` 的直链，网页链接自动过滤。

## 四、播放地址解密（encrypt）

- **encrypt=2**：`base64decode(url)` → 再 `URLDecoder("UTF-8")` → 真实 m3u8
- **encrypt=1**：仅 `URLDecoder("UTF-8")`
- 实测例子：DB线路《魅影神捕》解出 `https://vodcnd17.ajupf.com/20261002/Mk0WP07x/index.m3u8`，HTTP 200 可播

## 七、本次经验教训（新增知识点）

1. **播放页数据提取：花括号平衡是通用解法**，任何"var xxx={...}"结构的站都别死等分号/结尾符
2. **先测后传**（幺爸纪律）：本地 python 验证解密+直链 200 → 编译 jar → 模拟器 OK影视 实测 → 才上传
3. md5 联动：改 jar 必须同时改 b.json 顶层 `;md5;XXX`，先传 jar 再传 b.json
4. 站点对播放页偶发返回简化页时：带 Referer（详情页）+ PC UA 更稳定
5. b.json 只能字符串补丁重排，**禁止 json.dump**（会破坏格式导致 OK影视 解析失败）；重排 sites 用花括号平衡扫描块 + 保留原缩进 `\n                  ` 拼接
