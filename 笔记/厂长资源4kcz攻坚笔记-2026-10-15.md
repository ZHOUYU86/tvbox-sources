# 厂长资源 4kcz 攻坚笔记 — 2026-10-15

## 一、任务目标

把影视站「厂长资源」（www.4kcz.com）完整接入 OK影视 接口体系，核心要求：
1. **分类能浏览出内容**（分类精简成泛泰影那种 11 个：全部、豆瓣电影Top250、电影、国产剧、美剧、韩剧、日剧、华语电影、欧美电影、韩国电影、日本电影）
2. **能播放**
3. **能搜索**
4. 自用不传播

## 二、遇到的困难：SafeLine（雷池）WAF 动态加密

### 2.1 现象
- 4kcz 分类页在浏览器正常，但程序直接抓取时返回 **动态加密页**：
  - body 约 55 万字节
  - 含 `window.product_data={"name":"雷池","name_en":"SafeLine","product":"长亭"}`
  - 含"该网页已被加密保护"
  - 没有任何影视卡片数据
- Windows curl 直连分类页返回 **403**（TLS 指纹被拒）

### 2.2 自研 v12 方案（失败）
- 早期 jar 爬虫曾打通：分类/详情/播放跑通（模拟器《魅影神捕》播放成功），搜索曾通过逆向 SafeLine 468 挑战打通（v8 实证）
- 站方 WAF 升级后分类页变成"动态加密页"，所有分类"找不到数据"
- 编译 v12（新增 getCategory/isChallengePage，分类数组改 11 个）→ 部署后分类标签确实变 11 个，但各分类仍"找不到数据"
- logcat 显示 `cat direct len=556843 → cat jwt=eyJhbGci... → cat retry 0/1/2 code=200 len=554xxx`
- 结论：SafeLine 搜索挑战拿到的 JWT 对分类页动态加密**无效**——分类页和搜索页是**两种不同保护**

### 2.3 官方 API 与备用域名均走不通
- `api.php/provide/vod/?ac=list|detail` 全 404
- czzymovie.com 301 后无内容
- Windows curl 直连分类页 403（TLS 指纹被拒）

## 三、破局方案：复用「剧荒克星」jar（NewCzGuard）

### 3.1 从用户提供的泛泰影截图反查实现
- 泛泰影接口：`https://zhouyu86-bh1.pages.dev/fty/api.json`
- 其"厂长"源配置：`{"key":"厂长","name":"📔厂长┃秒播","type":3,"api":"csp_NewCzGuard","timeout":10,"playerType":2,"searchable":1,"quickSearch":1,"changeable":1}`
- 拉取其 spider.jar（fty_spider.jar，1113561 字节，md5=1AC25CCD1B5AC56FD19EB91C6F7DAF4D）
- apktool 反编译确认：
  - `NewCzGuard.smali` 只是继承 `BaseSpiderGuard`（两者均混淆）
  - assets 内含 `ftyguard_v7.so / ftyguard_v8.so / ftyshinidie.guard`（970KB 加密站点配置）
- 结论：剧荒克星用 **native so + 加密 guard** 解决 SafeLine，是商业方案，逐字节逆向成本过高，不值得自研

### 3.2 决策
直接复用剧荒克星 jar 作为我们的"厂长资源"源（用户授权"全权的帮我搞""全程全自动帮我搞"，且该 jar 已在泛泰影源上被验证可正常显示用户指定的 11 分类内容）。保留自研 v12 成果（分类精简 11 个 + 挑战兜底）作为过渡。

## 七、经验教训

1. **WAF 动态加密 ≠ 普通反爬**：SafeLine 分类页是动态加密 JS 挑战，分类/搜索/详情可能走不同保护路径，一个挑战通了不代表全部通
2. **商业 jar 内置 native so + 加密 guard**：逐字节逆向成本极高，**复用已验证可用的商业 jar 是捷径**（泛泰影的厂长源就是现成验证）
3. **jar 的 key 字段可能参与配置匹配**：复用 jar 时源 key 要和原配置一致（key=厂长）
4. **1.1MB 大 jar 首次加载慢**：dex 编译需 1-2 分钟，测试要耐心等待，不要误判为卡死
5. **模拟器 UI 操作技巧**：OK影视 源列表快速 swipe 可能不生效，用慢速长 swipe（1500ms+）更可靠；中文输入可装 ADBKeyboard 后用 `am broadcast -a ADB_INPUT_TEXT --es msg '中文'`
