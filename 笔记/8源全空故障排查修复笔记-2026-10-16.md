## 二、排查过程

### 2.2 逐步排查 jar 下载通道
- 8 个 jar 源全部 type=3，**共用顶层 spider 字段**指向 czzy_guard.jar
- 初期怀疑代理：ghproxy.net 拉 jar 只回 293936B（GitHub 真实 1113561B）→ md5 不匹配被拒

- **但 OK影视 源分类仍无限转圈 / 空**

### 2.3 最终根因：SafeLine 加固壳 jar
- czzy_guard.jar（md5 1ac25ccd...，1113561B）解包只 5 条目：
  - classes.dex（壳入口）
  - META-INF
  - assets/ftyguard_v7.so
  - assets/ftyguard_v8.so
  - assets/ftyshinidie.guard（加密站点配置）
- **无 class 文件 → OK影视 DexClassLoader 无法加载 → 全部 csp_ 源同时失效**
- GitHub commit 历史确认：该加固 jar 是 2026-10-15 12:06Z 推送的（消息含 "NewCzGuard 加 SafeLine"）

### 2.4 厂长（NewCzGuard）背景
- 厂长 = 4kcz.com（厂长资源），站点用 SafeLine（雷池）WAF 动态加密
- 标准接口 `api.php/provide/vod/` 被 WAF 拦截（返回 HTML 拦截页，非 JSON）
- 破局方案 = 复用「剧荒克星」商业 jar（NewCzGuard：native so + 加密 guard）——见 2026-10-15 厂长攻坚笔记
- 该商业 jar 同时是 SafeLine 加固壳（保护爬虫逻辑）→ OK影视 无法加载 → 厂长也空

**关键认识**：b.json 只能有一个顶层 spider，但 **每个 site 可独立配置 jar 字段**（OK影视/FongMi 标准支持）。

- 顶层 spider = **ddys_feikuai.jar**（未加固，md5 7c5d15ad...，268683B，含全部 7 个 csp 类：WwwDdys/Gqc/Feikuai/Cupfox/Www555/WwwDmxq/WwwQqys）
  → 低端/共青春/飞快/茶杯狐/555/大米星球/千千 恢复
- 厂长 site **加 jar 字段** = `https://zhouyu86-bh1.pages.dev/czzy_guard.jar;md5;1ac25ccd1b5ac56fd19eb91c6f7daf4d`
  → 厂长（csp_NewCzGuard）恢复

## 五、经验教训

1. **SafeLine 加固壳 jar 不能用于 TVBox**：1.1MB jar 只有 classes.dex + so + guard 文件，无 class → OK影视 直接无法加载，所有 csp_ 源一起失效
2. **别把商业加固 jar 当顶层 spider**：它只适合做单个源的 site 级 jar（且该源必须能加载 native so 的容器）
3. **site 级 jar 字段解决"一个 spider 装不下两类 jar"**：顶层放未加固多源 jar，特殊源（如厂长）单独 jar 字段，互不干扰
4. **pages.dev 直连最稳**：ghproxy.net 会截断大 jar（293936B），gh-proxy.com 可用但 pages.dev 直连更快更稳（模拟器内 curl 完整）
5. **本机 PowerShell 直连 pages.dev/raw.githubusercontent 会 DNS/TLS 失败（exit 35），模拟器内 curl 正常** —— 验证用模拟器内 curl，改配置用 GitHub API
6. **厂长搜索仍受限**（SafeLine 对搜索接口同样保护，NewCzGuard searchContent 数组越界）——与泛泰影接口的厂长源一致，需搜索时用其他源
