第1步：探测网站结构（Python 全链路实测，结论已定稿）
========================================================================

  目的：摸清"分类页/翻页/详情页/播放页/搜索"各自的真实 URL 和 HTML 结构，
        只有探测清楚了，jar 里的正则和拼接 URL 才不会瞎写。

  1.1 分类页探测
  ---------------- 
    访问（必须带浏览器 UA 和 Referer，否则 403）：
      https://hkys2.cc/v/dianying/   → 电影，列表 164 部
      https://hkys2.cc/v/dianshiju/  → 电视剧，128 部
      https://hkys2.cc/v/zongyi/     → 综艺，64 部
      https://hkys2.cc/v/dongman/    → 动漫，64 部
    另有细类：dongzuopian(动作片) / xijupian(喜剧片) 等
    页面里条目结构（jar 里 ITEM_PAT 匹配这个）：
      <a href="/show-304040/" title="绝命法官">...</a>
    海报：data-src="https://..."

  1.2 翻页探测（重要！真翻页在「影片库」，不在分类页）
  ----------------
    真实翻页 URL（每页 72 部，电影库共 58 页）：
      https://hkys2.cc/pianku-dianying--------2---/
      https://hkys2.cc/pianku-dianshiju--------2---/
      （格式：/pianku-<分类>--------<页码>---/）
    假翻页（千万别用）：/v/<分类>--------<n>---/
      —— 它返回的是全站 151 部混排，不是该分类第 n 页
    踩坑记录：最初 jar 用 /v/ 拼页码导致翻页内容不变，
             baksmali 反编译确认后把翻页模板改成 /pianku- 前缀。

  1.3 详情页探测
  ----------------
    详情 URL：https://hkys2.cc/show-304040/
    页面里有的关键字段（jar 的正则都从这取）：
      H1 标题:         <h1>绝命法官</h1>
      海报:            data-src="..."
      年份:            <span itemprop="datePublished">2025</span>
      简介:            <div class="video-info-content">...</div>
      导演:            <span class="video-info-itemtitle">导演：</span>
                       <div class="video-info-item video-info-actor">苏万聪...</div>
      主演:            <span class="video-info-itemtitle">主演：</span>
                       <div class="video-info-item video-info-actor">张家辉/胡杏儿/...</div>
      线路:            data-dropdown-value="https://hkys2.cc/paly-304040-1-1/"
      集数面板:        module-blocklist 里 <a>第01集</a>...
    ※ 特别注意：导演/主演的 HTML 结构是 video-info-itemtitle（不是旧模板
      module-info-item-title），这是 P4 演员空白的根因，见第7步。

  1.4 播放页探测（最关键）
  ----------------
    播放 URL：https://hkys2.cc/paly-304040-1-1/  （paly-<id>-<线路sid>-<集nid>/）
    页面里有一段 JS：
      var player_aaaa={"flag":"play","encrypt":1,"trysee":0,"points":0,
        "link":"https%3A%2F%2Fcdn.xxx.com%2F20250928%2F413_0deb1c54%2Findex.m3u8
        %26dyvip%26dianshiju%26next%3Dhttps%3A%2F%2Fhkys2.cc%2Fpaly-304040-1-2%2F"}
    处理三步（jar 的 decodeUrl + split 就干这个）：
      a) 找到 "player_aaaa=" 后面的 { } 对象
         —— 注意对象后面【没有分号】，Python 用 \{[\s\S]*?\}</script>
         —— jar 用 indexOf + 花括号深度计数提取，不受分号影响
      b) 取 link 字段 → 百分号解码（URLDecoder.decode UTF-8）
      c) 解码后结果里带着 & 参数：
         https://cdn.xxx.com/.../index.m3u8&dyvip&dianshiju&next=...
         【必须 split("&")[0] 切出纯 m3u8】，否则播放器拿整串请求失败
    实测：电影 m3u8 82,381B / 日剧 32,393B 均 HTTP 200

  1.5 搜索探测（结论：站方关闭，无法绕过）
  ----------------
    试了三种搜索形态 + suggest 接口，全部 403：
      /search------<关键词>/
      /search/<关键词>/
      /search?wd=...
      api.php?ac=videolist&wd=...   → 返回 "closed"
    实测 jar 请求 /search------关键词/ 拿到的页面标题是
      "Attention Required! | Cloudflare" —— 即 Cloudflare 反爬拦截页
    结论：搜索路径被站方挂在 CF 反爬下，jar 端无法绕过，
          json 里保留 searchable:1 但实际搜不到，需向用户说明。

  1.6 UA 敏感（整站通病）
  ----------------
    okhttp 默认 UA (okhttp/4.12.0) → 403
    浏览器 UA + Referer=https://hkys2.cc/ → 200
    jar 里 get() 方法统一带：
      User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 ...
      Referer: https://hkys2.cc/

第3步：手写 bean 数据类（最大坑 P1/P2，必读）
========================================================================

  3.1 为什么手写
  ----------------
    fongmi 加载 jar 后报：
      ClassNotFoundException com.github.catvod.bean.Class @ WwwHkys.homeContent:178
    排查：把本地 41 个 jar 全部扫描（scan_jar_bean.py），
         没有任何 jar 含 com/github/catvod/bean 标准类
         （唯一坏的 zip 是 keke.jar）
    结论：bean 包只能手写补全，没有现成可抄。

  3.2 手写的三个类（都在 bean\ 下）
  ----------------
    Class.smali  — 分类对象 {type_id,type_name}
    Vod.smali    — 影片对象（id/vodId/name/pic/actor/director/year/content/playFrom/playUrl...）
    Result.smali — 结果包装（get()/error()/vod(list)/page()/string() 静态方法）

  3.3 VerifyError 灾难史（P2，最深的坑）
  ----------------
    现象：补了 bean 后 fongmi 仍报
      VerifyError: Verifier rejected class com.github.catvod.bean.Result:
      java.lang.String com.github.catvod.bean.Result.string(...) @ WwwHkys.homeContent:192
    第一次误判：以为是循环寄存器 v3 未初始化，补 const/4 v3,0x0
              （md5=3afd3573… 仍报错，白改）
    真正根因（baksmali 反编译逐字节核对找到）：
      Result.smali 的 static string(Vod) 方法 .registers 4，方法只有 p0 一个参数，
      但代码里写成了 invoke-virtual p1, Vod->toJson
      —— p1 是越界寄存器，ART 校验器直接拒掉整个类（连带其他方法全不能用）
    修复：p1 → p0（用 p0 这个真实参数）
    验证：写寄存器扫描脚本，核对 Result/Vod/Class 全部方法
          满足 max p < .registers 才算 OK
    重打包 md5=1e07b105… → fongmi 分类页终于出数据（截图实锤）

第4步：打包流程（build_hkys_jar.py 一键完成）
========================================================================

  命令：python D:\tvbox\spider_dev\dashixiong\keke\build_hkys_jar.py
  内部做 3 件事：

    - 打包日志在 build_hkys_jar.txt
    - smali 汇编失败时 stderr 是 GBK 中文，Python 读 UTF-8 会崩，
      这时手动跑 java -jar smali assemble 把 2>&1 重定向到文件再读

  5.1 json 格式（当前版，332B）
  ----------------

    "spider": "http://127.0.0.1:8081/hkys2_v5.jar;md5;0310c17c9f7b1ec38eea607cb6a09f86",

  5.6 jar 缓存绕过（P6，每次更新必做）
  ----------------
    fongmi 把 jar 缓存在：

第7步：排障记录（P1~P6，按时间顺序，含根因与修复）
========================================================================

  P1. 首页空数据
      现象：fongmi 首页转圈/空白
      日志：ClassNotFoundException com.github.catvod.bean.Class @ homeContent:178
      定位：扫描 41 个 jar 无 bean 包 → 唯一坏 zip 是 keke.jar
      修复：手写 Class/Vod/Result 三件套
      结果：da8802f2(裂) → 1183bf1c(空) 仍不行

  P2. VerifyError（最有价值的坑）
      现象：VerifyError: Verifier rejected class com.github.catvod.bean.Result:
            java.lang.String Result.string(...) @ homeContent:192
      误判：以为是 v3 循环寄存器未初始化，补 const/4 v3,0x0 → 仍报错
      真因：Result.smali static string(Vod) 方法 .registers 4 只有 p0 参数，
            却 invoke-virtual p1, Vod->toJson → p1 越界 → 整个类被 ART 拒
      修复：p1→p0；写脚本核对 3 个 bean 全部方法 max p < .registers
      结果：重打包 md5=1e07b105… → 分类页终于出数据（截图实锤）

  P3. 播放失败（Input does not start with the #EXTM3U header / 3002）
      现象：所有线路都播不了
      日志：TV-player: {"parse":0,"jx":0,
            "url":"https://cdn.yzzy31-play.com/.../index.m3u8&dyvip&dianshiju&next=...",
            "header":{...}}
      定位：jar 只做了 URLDecoder.decode，没做 split("&")[0]
      修复：WwwHkys.smali playerContent 里 decodeUrl 之后插入：
              const-string v2, "&"
              invoke-virtual {v1, v2}, String->split(String;)[String;
              move-result-object v2
              const/4 v3, 0x0
              aget-object v1, v2, v3
      结果：v5 实测 FF/HD 线路 url 全是纯 m3u8，播放器出画面，3002 消失

  P4. 演员/导演空白（年份正常）
      现象：详情页年份 2025 有，但「主演」「导演」一行空白
      定位：抓详情页 HTML 实测 → 网站结构是
              <span class="video-info-itemtitle">主演：</span>
              <div class="video-info-item video-info-actor">...</div>
