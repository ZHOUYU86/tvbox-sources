## 三、四大硬伤 · 症状 → 排查 → 解法（本战核心经验）

### 坑 1：证书信任链问题（模拟器连不上、浏览器能开）
**症状**：模拟器 shell curl 直连 555 返回 000/超时；但模拟器内置浏览器、电脑浏览器都能打开 → 一度以为网站被墙。
**根因**：555 的证书链在 Android/okhttp 默认信任下校验失败（CertPathValidatorException）。
**解法**：createClient() 里加"信任全部证书"：
- X509TrustManager 全信任（checkServerTrusted 空实现）
- SSLContext.getInstance("TLS") + init 该 TrustManager
- hostnameVerifier 恒真
- **自定义 Dns 兜底**：返回上面 6 个 A 记录（防 DNS 污染/解析失败）

> 经验：安卓模拟器里"curl 连不上但浏览器能开"基本就是证书问题；服务端证书链不完整时直接信任全部证书最省事。

### 坑 2：gzip 乱码（主页空、不转圈）
**症状**：主页有分类 tab 但内容空、不转圈（日志抓到 22729 字节乱码）。
**根因**：手动加了 `Accept-Encoding: gzip, deflate` header，okhttp 认为服务端已解压、不再自动解压 → 拿到的是 gzip 压缩原始字节 → 解析全废。
**解法**：**删掉 gzip header**（headers() 只留 UA/Referer/Accept 三项），让 okhttp 自动处理。
**修复证据**：主页从乱码 → 127 条内容网格。

> 经验：okhttp 加 `Accept-Encoding: gzip` 会关掉自动解压！不手动设这个 header 反而安全。

### 坑 3：分类 tab 不显示（只有"推荐"）
**症状**：分类数据能返回，但主页顶部只有"推荐"一个 tab，电影/连续剧/动漫全不显示。
**根因**：homeContent 返回格式问题。最初用 `Result.get().vod(items).string()`，OK影视 不识别；对比已验收的 Cupfox 源，它是 `Result.string(list, vodList)` 格式。
**解法**：homeContent 统一改 `return Result.string(list, items);`（items 非空时也用它）。
**修复证据**：推荐/电影/连续剧/综艺纪录/动漫 五个 tab 全部显示；点"电影"返回 23 条、pagecount=4168 可翻页。

> 经验：jar 源 homeContent 的返回格式必须和成功源逐字对齐，`Result.get().vod().string()` 与 `Result.string(list, vod)` 在 OK影视 里行为不同，别想当然。

### 坑 4：搜索空（搜索页结构不同）
**症状**：主页正常，搜索关键词返回空列表。
**根因**：555 的**搜索页条目结构和首页不同**——首页是 `module-poster-item`，搜索页是 `module-card-item module-item` 嵌套 div 结构，首页解析逻辑搜不到条目。
**解法**：新增 `parseSearchList()`：按 `<div class="module-card-item module-item">` 出现位置计数、切块，再在每块内提取标题/链接/图；searchContent 首选 parseSearchList()，空结果兜底 parseList()。
**修复证据**：输入 zhanlang 出联想词 → 点"战狼2"出结果；用户最终确认"可以了，写好了，没有问题了"。

> 经验：同一站点的搜索页和列表页结构可能完全不同！解析新站先抓搜索页 HTML 对比，别只写一套解析。

## 五、上线部署（GitHub + Cloudflare Pages）

1. **合并 jar**：所有自写 jar 源（共青春 Gqc / 飞快 Feikuai / 茶杯狐 Cupfox / 555电影 Www555）**编进同一个 jar**，部署名 `gqc_feikuai.jar`（一个 jar 带 4 个 csp_ 类，OK影视 加载一次全有）。
2. **md5**：`Get-FileHash gqc_feikuai.jar -Algorithm MD5` → 新 md5 写入 b.json 的 spider 行。
3. **b.json 结构**（GitHub 仓库根）：
   - `spider` 行：`https://ghproxy.net/https://raw.githubusercontent.com/ZHOUYU86/tvbox-sources/main/gqc_feikuai.jar;md5;<md5>`
   - `sites` 列表：每个 jar 源一条 `{"key":"Www555","name":"555电影[自写jar]","type":3,"api":"csp_Www555","searchable":1,"quickSearch":1,"changeable":1}`
4. **上传方式**：GitHub Contents API（token 在 `D:\tvbox\_tools\github_token.txt`，注意文件带 BOM 要用 `utf-8-sig` 读）：
   - GET 旧文件拿 sha → PUT base64 内容 + sha 覆盖
   - 单文件 < 100MB 都可以 API 直传，比 git clone/push 稳（国内网络 clone 常断）
5. **部署**：Cloudflare Pages（tvbox 项目）绑定该仓库自动构建 → 线上 `https://tvbox-bh1.pages.dev/b.json`

> 经验：改 b.json 前**必须先拉 GitHub 线上最新版**再改（线上可能已有别人/之前加的源，比如兔小贝儿童），不要拿本地旧备份直接覆盖，会丢配置。

## 六、经验教训总结（下次直接抄）

1. 新站先抓首页/搜索页/详情页三份 HTML 存档，逐条核对条目结构，再写解析。
2. 安卓模拟器 curl 连不上但浏览器能开 → 证书问题 → 信任全部证书 + Dns 兜底。
3. 别手写 `Accept-Encoding: gzip`，交给 okhttp 自动处理。
4. homeContent 返回格式严格对齐已验收源（Result.string(list, vod)）。
5. 搜索页条目结构往往和列表页不同，单独写解析函数并兜底。
6. jar 里多埋 Log.d（TV-555/TV-home/TV-category），logcat 是唯一可靠的排查入口。
7. 上传线上前先 GET 拿 sha、基于最新版修改；token 文件 BOM 坑（utf-8-sig 读取）。
8. 一切改动以"模拟器实测通过"为验收标准，通过了才保存、才上传。
