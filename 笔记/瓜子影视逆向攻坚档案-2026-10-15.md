### 2. 响应结构（决定性证据）
```
{"code":200,"msg":"请求成功","data":{"response_key":"<32hex=16B>","keys":"<base64 128B>"}}
```
- **`keys` 恒为 128 字节**（indexList limit=1/5/20、playInfo 错误、signIn 错误全部 128B）
- **排除 AES 流式**（明文长度应随内容变）；RSA-1024 密文特征吻合
- **但**：app.so 内 **无任何 RSA 私钥**（PKCS#1/PKCS#8 DER 0 命中；长 hex/十进制大数全是 EC 曲线与 padding 常量；RSASigner/RSAEngine 为 pointycastle 库代码，**未被业务调用**）
- **结论**：keys 不是标准 RSA 私钥解密，也不是 KANGEQIU AES；**解密函数是自定义 Dart 代码，aotopsy 未标记为加密调用**

### 3. 解密函数定位（aotopsy 全量排查结果）
- 唯一 AES 解密链：`SportAesHelper.decryptFromBase64 → Encrypter.decrypt64 → AES.decrypt`（encrypt 包，key=`KANGEQIU@8868!~.` iv=`0200010900030207`，CBC+PKCS7）
- **该链只被 `SportAesInterceptor.onResponse`（data 为 string 时）与 `SportApiService._loadRemoteBaseUrls`（远程配置）调用**——**没有业务代码调用它解 keys**
- 拦截器全集：SportAesInterceptor / AuthInterceptor / LogInterceptor / ImplyContentTypeInterceptor——**无第二解密拦截器**
- Encrypter/AES/Key/IV 实例化：**全局仅 SportAesHelper 一处**
- `response_key`/`keys` 字符串在 string_value_xref **0 命中**（字段名非硬编码——运行时 JSON 动态解析，静态无法追）

### 4. keys 解密暴力尝试（全部失败，勿重复）
- AES-CBC/ECB：key=KANGEQIU、response_key(hex字节)、response_key(字符串/AES-256)、FIXKEY+response_key、response_key+FIXKEY、token/token_id 各种派生、MD5/SHA1/SHA256 派生、XOR——**全部 Padding incorrect 或乱码**
- RSA 私钥：ASN.1 DER、hex 字符串、十进制 BigInt、PEM/base64——**全部 0 命中**

### 5. token 传递方式（实测无影响）
token 放 body / header / query / Authorization 头，响应结构完全一致（仍为 response_key+keys）。
注册流程：`UserStore.tryLogin → registerGuest(deviceId) → /App/Authentication/Device/signIn → 返回 token → StorageStone 存储 → AuthInterceptor 每次请求自动注入 token + version`。

### 6. Android 版（瓜子影视_v3.0.5.2_Android纯净版.apk）——独立线索
- **原生 Android 应用**（classes.dex 7MB，**非 Flutter**，与 Windows 版不同实现）
- 核心逻辑在加固 so：`assets/l2eb3cd5f_a64.so`（签名校验）、`lib/arm64-v8a/libkiwi.so`（字符串加密，0 命中）
- classes.dex 字符串：接口域名/密钥 **0 命中**（已混淆/加固）
- **静态不可挖，但 Java 层可动态 hook（模拟器）**

## 二、下一步建议（安全优先，不再动 Windows 运行环境）

⚠️ 教训：Windows 版用 Frida spawn 运行 **两次触发系统意外关机（蓝屏）**（日志 6008，4:23/4:30），**已停用一切 Windows 动态注入**。

### 路线 A（推荐）：Android 模拟器 Frida hook（隔离环境，安全）
- 雷电/夜神模拟器 root 后装 Frida-server
- hook 目标（原生 APP）：
  1. OkHttp/HttpURLConnection 响应读取 → 拿到解密前/后的完整 JSON
  2. `javax.crypto.Cipher.doFinal` → 直接抓 AES/RSA 解密明文
  3. libkiwi.so 导出函数（需先 strings/IDA 定位）
- 产出：keys 解密算法 + 会话密钥 → 即可在 jar 里复现

### 路线 B：Windows 版 Dart 静态深挖（继续 aotopsy）
- 定位自定义解密函数：在 evidence.jsonl 中找"读 data['keys'] 的调用者"（Map 动态访问无法直接 grep，需按 data 字符串引用反查 ApiResult.success 构造链）
- 用 signal_cfg.dot / aotopsy.r2 反汇编 `ApiResult.success` 看它如何处理 keys
- 产出：还原自定义解密算法

### 路线 C（兜底）：放弃直连，抓"播放地址"降级方案
- 若解密始终不破：考虑在 Android 模拟器内用官方 APP 播放，抓取播放 URL 特征，写成"壳源"（可靠性低，不推荐）

## 2026-10-15 深夜·最终攻坚结论（本段新增）

### 本轮新增尝试（全部失败，勿重试）
1. **MITM 抓包（Windows）**：搭好完整 HTTPS 代理（监听443、自签证书含5域名SAN、导入系统信任、hosts指向127.0.0.1、真实IP直连+SNI转发）——链路自测成功（请求200）。**但启动瓜子影视 Windows 版后 APP 立即崩溃退出**（还原 hosts 后正常启动）→ **Windows 版有证书固定（pinning）**，MITM 证书被拒。MITM 方案对 Windows 版不可行。
2. **模拟器 hook（雷电9 x86_64）**：模拟器在线、APK 安装成功（包名 com.ja4f8ea425.u09b70cf3e.bdfbc5096b20260826），启动后 **SIGABRT 崩溃**——logcat 显示 libhoudini ARM 转译加载加固壳 l2eb3cd5f.so 后崩溃。加固壳在 x86 模拟器 ARM 转译下必崩，模拟器 hook 不可行（需 ARM 真机）。
3. **RK 全分片密钥穷举**：RK(16B) 分片 hi/lo × MD5/SHA1/SHA256/FIXKEY 拼接 × IV(RK/hi/lo/FIXIV/ZERO/keys前16B) × CBC/ECB = **120 组全部 Padding 失败**。

### 最终定论
- 瓜子影视响应加密（response_key+keys）为**总闸**：所有业务接口（indexList/playInfo/search/signIn）返回固定 {response_key, keys} 包裹，必须先解 keys 才能拿数据。
- 解密算法/密钥位于**加固壳 native 层**（Windows: app.so；Android: libkiwi/l2eb3cd5f.so），静态逆向（aotopsy/dex/字符串/RSA/AES全排列）已彻底穷尽，无法定位。
- 动态路径三条全堵死：Windows 注入（用户电脑两次6008，禁）、Windows MITM（pinning）、x86 模拟器（ARM转译崩溃）。
- **结论：当前 Windows x86 环境下瓜子影视 keys 无法破解，做不成自研 jar 源。唯一可行路径是 ARM 真机 + Frida hook（需用户手机配合）。**
