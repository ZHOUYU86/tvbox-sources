日期：2026-10-15

## 〇、一句话结论

**低端影视的搜索接口根本不是网页搜索（/search?keyword=），而是两个内部 POST JSON API。** 爬虫必须调
`POST /api/search-online {"q":词}` 搜结果、`POST /api/get-online-detail {"source_key","vod_id"}` 拿分集，
否则永远搜不到。本文记录"为什么搜不到 → 怎么扒出真接口 → 怎么改 → 为什么现在能搜到"的完整过程。

## 一、站点概况

- 站点：https://ddys.io（低端影视）—— 高质量 m3u8 直链源，无解析站
- 分类：`/movie` 电影 `/series` 剧集 `/variety` 综艺 `/anime` 动漫 `/rating` 高分 `/popular` 热门 `/year/2026` 年份
- 分页：`/movie/page/{n}`（电影 193 页），末页链接 pagination-last
- 列表卡片：`<div class="movie-card">` 内 `<a href="/movie/{slug}">` + `<img alt=片名>`
- 详情页：`/movie/{slug}`，线路直接在 HTML：`onclick="switchSource(id, 'url', 'format')"`，
  url 即标准 TVBox 分集串（`第01集$https://.../index.m3u8#第02集$...`），电视剧 3 条线路（lzcdn27/bfvvs/jisuzyv）、电影 2 条
- 播放：m3u8 直链 parse:0 jx:0 直放，需 Referer https://ddys.io/
- 搜索：**JS 动态渲染（关键坑点，见第三节）**

## 三、搜索攻坚全过程（本次核心）

### 3.1 现象

- 用户反馈：模拟器、手机 **搜索源列表里都没有"低端影视"**，搜不到低端影视内容
- 首页/分类/详情/播放全部正常 —— 只有搜索不行

### 3.2 初步排查（排除的假设）

1. **怀疑 FongMi 配置 searchable 没开？** → 查线上 b.json：Ddys `searchable=1 quickSearch=1`，配置正确，排除
2. **怀疑缓存？** → 手机端和模拟器都搜不到，不是单端缓存问题，排除
3. **怀疑 FongMi 源列表不显示 jar 源？** → 同配置的飞快TV/555电影（同为 type=3 jar 源）能搜到，排除

### 3.3 定位关键线索

- 模拟器长按影片触发自动搜索（quickSearch）：结果源列表出现量子资源/555电影/飞快TV 等**有结果的源**，低端影视不在其中
- logcat 查 `TV-DDYS` 日志：只有 `home items=24` 和 `cat ...`（分类翻页），**完全没有 search 日志**
  → 结论：FongMi 调用了搜索，但低端影视爬虫 searchContent **要么返回空要么没被调**；结合"列表不显示该源"，
  说明 FongMi 会把**搜索接口返回空/报错的源从结果列表里隐藏** —— "列表里没有低端影视"其实是搜索接口坏掉的表象

### 3.4 扒出真实搜索 API（关键突破）

用 Python 直连实测 `/search?keyword=长生契`：
- HTML 长度 115390，但 `movie-card count=0`、无结果 DOM，页面顶部 alt 全变成**热门推荐**（老九门、热浪之外…）
  → **搜索结果是 JS 动态加载的，服务端 HTML 里没有结果**
- 反查页面内联 JS（找 `/api/` 路径、fetch 调用、search-online 关键字）：
  - `api paths` 命中：`/api/search-online`、`/api/get-online-detail`、`/api/search-source`、`/api/search-suggest?q=`、`/api/hot-movies`…
  - 在 `search-online` 附近 JS 源码里看到**完整调用格式**：
    ```javascript
    fetch('/api/search-online', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ q: searchKeyword })
    })
    ```
- 实测：GET `/api/search-online?keyword=xxx` → `{"success":false,"message":"Method not allowed"}`（405）
  POST 表单 `keyword=xxx` → `"搜索关键词不能为空"`（参数名不对）
  **POST JSON `{"q":"长生契"}` → 成功！** 返回 6 条结果（不同源聚合：1号厅/2号厅/3号厅/4号厅）

### 3.5 详情接口（搜索结果点进去怎么拿分集）

- 搜索结果卡片点击 → JS 再调：
  ```javascript
  fetch('/api/get-online-detail', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ source_key: item.source_key, vod_id: item.vod_id })
  })
  ```
- 实测 POST JSON `{"source_key":"bfzy","vod_id":"163492"}` → 成功返回：
  `data.play_list[].episodes[]`（name=第1集, url=m3u8 直链），多源 = 多线路
- 注意：**GET 该接口返回 403**，必须 POST + JSON
- 搜索结果 vod_id 是**数字 ID**（如 163492），`/movie/158338` 这类数字 slug 打不开（fallback 回首页）——不能复用网页详情逻辑

### 3.6 爬虫改造（WwwDdys.java v2）

1. **searchContent**：`POST /api/search-online {"q":key}` → 解析 `data[]`：
   - `id = source_key + "|" + vod_id`（编码，供 detailContent 还原）
   - `Vod(id, vod_name, vod_pic, vod_remarks)` + setVodYear
2. **detailContent**：ids[0] 含 `|` → 走 `detailByApi()`：
   - 拆分 source_key/vod_id → `POST /api/get-online-detail`
   - 解析 play_list[] → 每 source 一条线路，episodes 拼 `第N集$m3u8#...`
   - 填 vod_director/vod_actor/vod_content
   - 不含 `|` 的普通 slug 仍走 `/movie/{slug}` 原逻辑
3. **编译坑**：okhttp `RequestBody.create(MediaType, String)` 报 `找不到okio.ByteString的类文件`
   （工程 classpath 缺 okio，GET 不用 RequestBody 所以之前没暴露）
   → 改**纯 JDK HttpURLConnection 手写 POST**（setRequestMethod POST / doOutput / setRequestProperty / 读流），编译通过
4. 编译产物：`ddys_v2.jar`（270081 字节，md5 b2d05d6a1471910a3c8b2ebd85e18786）

## 四、根因总结（为什么搜不到 → 为什么现在能搜到）

| 阶段 | 搜索接口 | 结果 |
|---|---|---|
| v1 爬虫 | GET /search?keyword= 解析 HTML | 页面 JS 动态渲染，HTML 无结果 → 永远 0 条 → FongMi 从搜索列表隐藏该源 |
| v2 爬虫 | POST /api/search-online {"q"} + POST /api/get-online-detail | 返回真实结果 → 源出现在搜索列表第一位 → 搜索可用 |

一句话：**"列表里没有这个源" ≠ 配置没开，而是该源搜索接口返回空，FongMi 自动隐藏。** 排查顺序应是
"先证明搜索接口能返回数据"，而不是先怀疑 App 配置。

## 五、经验沉淀（下个源直接套用）

1. **先验证站点搜索是 SSR 还是 JS 渲染**：curl 页面 HTML，数结果 DOM（movie-card count），
   有结果才是 SSR；没有就 100% 是 JS 动态，必须找 API
2. **找真实 API 的方法**：抓页面内联 JS，grep `/api/`、`fetch(`, `axios.`, `search.*fetch`；
   ddys 的搜索 JS 逻辑全部内联在 /search 页 HTML 里，不用找外部 js 文件
3. **POST JSON API 的坑**：GET 405 / 表单 POST 参数名错 / JSON body 字段名不同（ddys 用 `q` 不是 `keyword`）——
   一定要从 JS 源码里抄**原样 body**，不要猜
4. **搜索结果的 id 不能直接当详情 slug**：聚合 API 返回数字 vod_id + source_key，
   详情必须走对应 API（POST），网页详情路由对数字 id 无效
5. **工程编译环境缺 okio**：jar 爬虫里 POST 一律用纯 JDK HttpURLConnection，别用 okhttp RequestBody
6. **jar 更新必须换新文件名**（bttwo 笔记铁律再次验证）：覆盖同名 jar，FongMi 按 URL hash 缓存旧版，永远跑旧逻辑
7. **FongMi 搜索源列表 = searchable=1 的源，但接口返回空的会被隐藏** —— "搜不到"先查接口，别先改配置
